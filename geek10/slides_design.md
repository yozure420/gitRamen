### スライド 1：フック＋作品紹介（20 秒）

- **フック（チームの実体験）**：チームで開発していたとき、Git コマンドの使い方を知らず、教えても理解できず、**毎回リポジトリを消して clone し直している**メンバーがいて大変だった
- 聞き手が「あるある」と思える場面から入り、すぐに結論を言う：「だから、Git のコマンドを打つとラーメンができるゲームを作りました」
- 作品名 gitRamen、チーム名「我ら家系！」、メンバー（yozure、あひる）を載せる

### スライド 2：課題（10 秒）

- Git は、コマンドを覚えても、それぞれの操作が何をしているのかイメージしにくい
- Git のコマンドは約 145 個あり、今も更新され続けている。なのに、実際に使われるのは十数個だけ
  - 出典：YouTube の動画 https://youtube.com/shorts/kjSONxaPuvU （スライドに出典として小さく載せる）

### スライド 3：解決 ― Git の操作をラーメン店の仕事に置き換えた（12 秒）

- 上の対応表のうち、`pull` → `add` → `commit` → `push` の 4 つを流れとして図にする
- 原稿：「`git pull` で注文を受け、`git add` で具材を乗せ、`git commit` で注文を確定し、`git push` で配膳します。Git の操作そのものがゲームの操作になります」

### スライド 4：こだわり・独自性・可能性（13 秒）

時間が短いので、スライドには各項目 1 行だけ載せ、詳しくは原稿で補う。

- **こだわり**
  - 実際の Git コマンドの意味を絶対に崩さない
  - 遊ぶときの安心感を優先し、多くの人が知っている「寿司打」のようなタイピング UI にした
  - Git のリリース情報や GitHub の更新情報を載せるニュース画面がある（最新の Git に触れられる）
- **独自性**
  - 言い方は「Git のコマンドを打って遊ぶタイピングゲームは、私たちは他に見たことがありません」程度にとどめる。既存のサービスとの比較は入れない
- **可能性（こんな人に届く）**
  - Git を勉強したいけど、何を言っているのか分からない／何で勉強したらいいか分からない人
  - Git コマンドをアウトプットしたいが、制作をしたいわけではない人
  - 英字でタイピング練習をしたい人（寿司打は日本語ベース）
  - AI エージェントの作業ログを見て「今 Git で何をしているか」が分かるようになる

  - 上のコースほど、実際の Git の使いどころがギミックとして注文に入る
    - 中級：`stash`（常連さんの割り込み）、`reset --soft`（コール間違い）、`commit --amend`（注文変更）
    - 上級：`reflog`（丼が消えた！）、`bisect`（スープがまずい！）
    - 超上級：`write-tree` / `commit-tree` / `update-ref`（親方の検品）

### スライド 6：技術レベル①　Git の手順をそのまま判定するゲームロジック（30 秒）

- 注文ごとに手順（例：`stash` → `stash pop`、`reflog` → `reset --hard HEAD@{1}`）を持ち、順番・引数・ハッシュまで照合する
- エピソード：Git の手順どおり `branch` → `checkout` で新しいレーンに移って push すると、毎回「誤配達」になるバグがあった。配達先が注文を受けた時点のレーンに固定されていたのが原因。直して、Git の手順どおりに遊べば勝てるようにした

### スライド 7：技術レベル②　本番運用で出会った問題と、決勝に向けた発展（30 秒）

- SQLite の `ALTER TABLE` は、トランザクションの中でもその場で確定する。本番は gunicorn の 4 ワーカーが同時にマイグレーションを走らせるので、`BEGIN IMMEDIATE` で自前で囲み、競合しても失敗しないようにした（古いスキーマの DB 20,000 行に 4 プロセスから同時に 12 回かけて確認）
- 外部 API 4 件を並列取得：直列 808ms → 並列 205ms（擬似的に 200ms の遅延を入れて測定）
- 品質：Vitest・Playwright（E2E）・pytest のテストを、pull request ごとに CI で自動実行
- 決勝に向けた発展：ワーカーをまたいだキャッシュの共有（Redis など）、ゲームループの描画負荷を計測して最適化
